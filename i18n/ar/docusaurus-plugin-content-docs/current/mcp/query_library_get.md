تسترد أحد إدخالات [Query Library](pathname:///docs/query-library/) بواسطة قيمة `id` التي تعيدها الأداة [`query_library_search`](/mcp/query_library_search).

عند حذف `params` أو تركها فارغة، تعيد الأداة القالب الخام وتعريفات المعلمات والملاحظات. ومع كائن `params` غير فارغ، يتحقق الخادم من صحة القيم ويدرجها في القالب. ولا تعيد SQL إلا عند نجاح إنشائه من القالب. ولا يحتاج النموذج إلى إدراج القيم بنفسه.

لا تنفذ هذه الأداة SQL ولا تتحقق من بيانات الاعتماد السحابية. ويختلف تحققها من صحة المعلمات عن [`validate_select_query`](/mcp/validate_select_query)، التي تحلل جملة `SELECT` وتخططها على الموفر المثبت.

## الإدخالات {#inputs}

| الوسيطة | مطلوب | الوصف |
|--|--|--|
|`id`|نعم|معرف الاستعلام من نتائج البحث، على سبيل المثال `aws/s3/buckets-list`.|
|`params`|لا|كائن يربط أسماء المعلمات الواردة في التعريف بقيمها. احذفه أو حدّد `{}` لفحص القالب دون إنشاء SQL منه.|
|`format`|لا|تنسيق عرض النص: `markdown` أو `json`. عند حذفه، يتم استخدام إعداد العرض في الخادم (`markdown` افتراضيًا).|

يتم رفض المعلمات غير المعروفة. ويتم الإبلاغ في `missing_params` عن المعلمات المطلوبة التي لم تقدم لها قيم ولا قيم افتراضية. ويتم التحقق من القيم المقدمة مقابل الأنواع والقيود الواردة في التعريف؛ وتعد العناصر النائبة التي لم يتم حلها أخطاء.

## الإخراج {#output}

طريقة العرض النصية الافتراضية هي كتلة KV تتضمن الهوية وحالة تعديل البيانات والأداة التالية وحالة الصحة وروابط المصدر وأي قالب أو SQL ناتج أو أخطاء. استخدم الحمولة المنظمة أو `format: "json"` للحصول على بيانات التعريف الكاملة:

| الحقل | الوصف |
|--|--|
|`id`, `title`, `description`|هوية الإدخال وملخصه.|
|`mutation`, `verb`|ما إذا كان الإدخال يغير الموارد، ونوع عمليته عند تعريفه (`select` أو `mutation` أو `lifecycle`).|
|`next_tool`|أداة التنفيذ الخاصة بالإدخال: `run_select_query` أو `run_mutation_query` أو `run_lifecycle_operation`. لا يستدعيها الاسترداد.|
|`params`|تعريفات المعلمات مع الأسماء والأنواع ومؤشرات الإلزام وأي قيم افتراضية أو أوصاف أو أمثلة أو قيم تعداد أو أنماط.|
|`template`, `notes`|القالب الخام وملاحظات المؤلف، وتعاد عند حذف `params` أو تركها فارغة.|
|`rendered`, `valid`|ما إذا كانت محاولة إنشاء SQL من القالب قد جرت ونجحت. كلاهما `false` عند فحص القالب الخام.|
|`sql`|SQL الناتج، ولا يوجد إلا بعد نجاح إنشائه من القالب.|
|`missing_params`, `unknown_params`, `errors`|تفاصيل التحقق من الصحة عند فشل إنشاء SQL من القالب. لا تنفذ SQL حتى يتم حل هذه المشكلات.|
|`auth`, `permissions`|عند تعريفها، متغيرات البيئة الخاصة ببيانات الاعتماد والأذونات الأصلية للموفر اللازمة للتنفيذ. ولا يحتاج الاسترداد نفسه إلى أي منهما.|
|`cost`, `outputs`, `related`|عند تعريفها، تلميحات حول التوزيع المتوازي والتكلفة، وأوصاف أعمدة النتائج، ومعرفات الإدخالات ذات الصلة.|
|`doc_url`|صفحة المكتبة المخصصة للقراءة البشرية.|
|`source_tier`, `source_url`, `stale`|منشأ المحتوى: `primary` أو `fallback` أو `snapshot`، وعنوان URL الخاص به أو مساره المضمن، وما إذا كان المحتوى قد قدم من ذاكرة التخزين المؤقت أو اللقطة بعد فشل الحصول عليه.|

يعيد المعرف غير المعروف أو غير صحيح التنسيق خطأ. استخدم `query_library_search` للعثور على معرفات صالحة.

* * *

## التقييد {#gating}

مسموح في جميع أوضاع الخادم، مع مراعاة قائمة السماح للأدوات التي تم تكوينها. لا يترتب على استرداد قالب تعديل بيانات أو دورة حياة أو إنشاء SQL منه أي تأثير على جانب السحابة، ولا يحتاج إلى موافقة. أما تنفيذ SQL الذي تعيده الأداة فهو استدعاء منفصل يخضع لـ [وضع الخادم](/command-line-usage/mcp#server-modes).

* * *

## مثال {#example}

ابدأ بفحص أحد الإدخالات:

```json
{
  "id": "aws/s3/buckets-list"
}
```

ثم حدّد منطقة التوجيه المطلوبة له:

```json
{
  "id": "aws/s3/buckets-list",
  "params": {
    "region": "us-east-1"
  }
}
```

بعد التحقق من `rendered` و`valid`، تحقق من صحة جملة `SELECT` التي تعيدها الأداة باستخدام [`validate_select_query`](/mcp/validate_select_query). ثم استخدم الأداة المذكورة في `next_tool` لتنفيذها، مع تمرير قيمة `sql` المرجعة وتعيين `source` إلى قيمة `id` الخاصة بإدخال المكتبة لنسبة التنفيذ إليه. وتلزم بيانات اعتماد الموفر وأذوناته وقت التنفيذ.
