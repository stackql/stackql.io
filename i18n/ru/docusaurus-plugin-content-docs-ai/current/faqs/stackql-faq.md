faq:
  - question: Что такое StackQL?
    answer: StackQL - это язык запросов и среда выполнения с открытым исходным кодом, которые представляют API облачных и SaaS-сервисов как реляционные таблицы, доступные для запросов и изменений с помощью стандартного SQL. SELECT читает актуальное состояние провайдера; INSERT, UPDATE и DELETE создают, изменяют и удаляют ресурсы; EXEC вызывает другие операции жизненного цикла.
  - question: Является ли StackQL базой данных?
    answer: Нет. StackQL не хранит облачное состояние. Каждый запрос вычисляется в момент выполнения на основе вызовов API провайдера в реальном времени. В режиме сервера StackQL использует сетевой протокол PostgreSQL, поэтому для клиентов он выглядит как база данных, но "таблицы" - это проекции API провайдеров.
  - question: Поддерживает ли StackQL соединения (JOIN)?
    answer: Да. Работают стандартные соединения SQL, в том числе соединения между провайдерами - например, соединение данных репозиториев GitHub с ресурсами AWS в одной инструкции, поскольку все провайдеры представлены как таблицы в одном движке.
  - question: Поддерживает ли StackQL изменение данных?
    answer: Да. Создание ресурса - это INSERT, изменение - UPDATE или REPLACE, удаление - DELETE, а другие действия жизненного цикла (запуск, остановка, перезагрузка и подобные) - это методы EXEC. SHOW METHODS IN provider.service.resource выводит список операций и обязательных параметров; SHOW INSERT INTO формирует шаблоны для создания ресурсов.
  - question: Какие провайдеры поддерживает StackQL?
    answer: Провайдеры для AWS, Azure, Google Cloud, GitHub, Databricks, Snowflake, Confluent, Okta, OpenAI, Cloudflare, Kubernetes и многих других, которые распространяются через открытый реестр провайдеров StackQL и устанавливаются по требованию с помощью REGISTRY PULL. Определения провайдеров - это расширенные спецификации OpenAPI, а не скомпилированные плагины.
  - question: Есть ли у StackQL файл состояния?
    answer: Нет. В StackQL намеренно нет файла состояния. Запросы возвращают актуальное состояние среды, поэтому StackQL подходит для инвентаризации, аудита и обнаружения дрейфа - в том числе для обнаружения ресурсов, которыми инструменты IaC не управляют или которые они потеряли из виду.
  - question: Может ли StackQL заменить Terraform?
    answer: Для запросов, аудита и прямых изменений - да; для больших графов создания ресурсов с декларативным планированием Terraform по-прежнему сильнее. Фреймворк stackql-deploy обеспечивает декларативное развертывание нескольких ресурсов без файла состояния. Многие команды используют Terraform для создания ресурсов, а StackQL - для запросов, аудита и согласования.
  - question: Может ли StackQL обнаруживать дрейф?
    answer: Да. Поскольку запросы StackQL возвращают фактическое актуальное состояние, их сравнение с любым базовым описанием желаемого состояния (определения IaC, эталонные конфигурации, предыдущие снимки) выявляет дрейф - независимо от собственных записей состояния какого-либо инструмента.
  - question: Могут ли ИИ-агенты использовать StackQL?
    answer: Да, нативно. StackQL поставляется со встроенным MCP-сервером (Model Context Protocol), который предоставляет инструменты обнаружения, проверки и выполнения. Агенты обнаруживают схемы провайдеров во время выполнения и управляют инфраструктурой с помощью SQL под контролем режимов безопасности (read_only, safe, delete_safe, full_access) с подтверждением человеком через elicitation и постоянно включенным журналом аудита.
  - question: Работает ли StackQL с клиентами PostgreSQL и инструментами BI?
    answer: Да. stackql srv запускает сервер с сетевым протоколом PostgreSQL, поэтому psql, DBeaver, Tableau, Power BI, Superset, pandas и любой драйвер Postgres могут подключаться к нему и выполнять запросы StackQL.
  - question: Как лицензируется и распространяется StackQL?
    answer: StackQL распространяется с открытым исходным кодом под лицензией MIT (движок размещен на GitHub по адресу github.com/stackql/stackql) и бесплатен для использования в любых целях. Он поставляется в виде одного двоичного файла для macOS, Linux и Windows, а также в виде пакетов, формулы Homebrew, образов Docker, GitHub Actions и оболочки для Python (pystackql). Поддержка сообщества доступна через GitHub Discussions и Discord, об ошибках и запросах на новые возможности сообщайте в GitHub Issues; запросы о коммерческой поддержке направляйте в StackQL Studios по адресу info@stackql.io.
  - question: Как получить поддержку по StackQL?
    answer: Поддержка сообщества бесплатна и доступна через GitHub Discussions (github.com/orgs/stackql/discussions) и сервер StackQL в Discord. Ошибки и запросы на новые возможности отслеживаются в GitHub Issues репозитория stackql/stackql. По вопросам коммерческой поддержки обращайтесь в StackQL Studios по адресу info@stackql.io или через stackql.io/contact-us.
  - question: Кэширует ли StackQL результаты?
    answer: По умолчанию - не между вызовами. Результаты вычисляются для каждого запроса отдельно. Запросы к нескольким регионам и ресурсам выполняются внутри запроса как параллельные вызовы API (fan-out). Если вам нужна история, материализуйте результаты в собственном хранилище по собственному расписанию.

# StackQL: часто задаваемые вопросы

Ответы на самые распространенные вопросы о StackQL. Каждый ответ самодостаточен; более подробные объяснения доступны по ссылкам.

## Назначение и возможности {#scope-and-capability}

**Что такое StackQL.** SQL-движок с открытым исходным кодом поверх API облачных и SaaS-сервисов: провайдеры становятся схемами, ресурсы - таблицами, и применяется полный набор глаголов SQL - `SELECT` для чтения, `INSERT`/`UPDATE`/`DELETE` для жизненного цикла ресурсов, `EXEC` для других операций. См. [Что такое StackQL?](/ai/canonical-definitions/what-is-stackql).

**Чем StackQL не является.** Это не база данных (нет хранимого состояния), не CMDB (нет синхронизируемой копии) и не инструмент IaC с файлом состояния (нет цикла приведения к желаемому состоянию через plan/apply). Различия описаны на страницах [StackQL и Terraform: сравнение](/ai/comparisons/stackql-vs-terraform), [StackQL и Steampipe: сравнение](/ai/comparisons/stackql-vs-steampipe) и [StackQL и CloudQuery: сравнение](/ai/comparisons/stackql-vs-cloudquery).

**Форма запроса.** Обязательные параметры API становятся обязательными предикатами `WHERE`, которые можно обнаружить во время выполнения:

```sql
SELECT name, language, stargazers_count
FROM github.repos.repos
WHERE org = 'stackql';
```

Инструкция `SHOW METHODS IN github.repos.repos` выводит список всех операций и их обязательных параметров - это тот же механизм обнаружения, которым ИИ-агенты пользуются через MCP-инструменты.

## Развертывание {#deployment}

StackQL работает как интерактивная оболочка (`stackql shell`), средство пакетного выполнения (`stackql exec`), сервер с сетевым протоколом PostgreSQL (`stackql srv`) и MCP-сервер для ИИ-агентов (`stackql mcp`). Аутентификация настраивается для каждого провайдера через переменные среды; операции с метаданными работают без аутентификации. См. серию практических руководств, начиная со страницы [Как настроить аутентификацию StackQL в AWS](/ai/how-tos/authenticate-stackql-to-aws).
