# StackQL и CloudQuery: сравнение

CloudQuery - это фреймворк ELT с открытым исходным кодом для облачных активов: плагины-источники извлекают данные о ресурсах у поставщиков и по расписанию загружают их в целевую базу данных, где вы выполняете запросы к снимкам на SQL этой базы данных. StackQL переворачивает эту архитектуру: SQL-запросы выполняются непосредственно к API провайдеров в момент выполнения запроса, без шага синхронизации и без хранимой копии, - и тот же движок может изменять ресурсы, а не только читать их.

## Когда что использовать {#when-to-use-which}

Используйте **CloudQuery**, если:

- Вам нужна **история**: снимки на определенный момент времени, сохраняемые между синхронизациями, для анализа тенденций, расследования инцидентов или подтверждения соответствия требованиям.
- Вы хотите хранить данные об активах рядом с другими данными хранилища данных, чтобы соединять их в существующем стеке BI и аналитики (BigQuery, Snowflake, Postgres).
- Задержка запросов важнее актуальности: запрос к локальной базе данных выполняется быстрее, чем множество параллельных вызовов API.

Используйте **StackQL**, если:

- Вам нужно **текущее состояние**: проверки безопасности, обнаружение дрейфа, эксплуатационные запросы и любые решения, на основе которых средство автоматизации или ИИ-агент будет действовать немедленно.
- Вы не хотите эксплуатировать конвейер синхронизации и целевую базу данных, чтобы получать ответы на вопросы.
- Вам нужны операции записи - создание, обновление или удаление ресурсов - в том же инструменте и на том же языке, что и запросы.
- Потребитель - агенты: MCP-сервер StackQL напрямую предоставляет обнаружение, проверку и контролируемое выполнение; целевая база данных CloudQuery ничего не знает об API провайдера.

В больших масштабах эти инструменты дополняют друг друга: StackQL - для запросов в реальном времени и действий, CloudQuery (или результаты StackQL, материализуемые по расписанию) - для долгосрочного хранения.

## Сравнение архитектур {#architectural-comparison}

| Критерий | CloudQuery | StackQL |
|---|---|---|
| Модель | Извлечение и загрузка, запросы к копии | Запросы к источнику в реальном времени |
| Актуальность | На момент последней синхронизации | На момент выполнения запроса |
| История | Встроенная (сохраняемые снимки) | Не сохраняется (материализация вручную) |
| Необходимая инфраструктура | Планировщик синхронизации + целевая база данных | Один двоичный файл |
| Операции записи в облако | Нет | INSERT / UPDATE / DELETE / EXEC |
| Определение провайдеров | Плагины-источники на Go | Декларативные расширенные спецификации OpenAPI |
| Диалект запросов | SQL целевой базы данных | SQL StackQL (сетевой протокол, совместимый с Postgres, в режиме сервера) |
| Интерфейс для агентов | Нет (запросы к целевой базе данных) | Встроенный MCP-сервер с режимами безопасности |

```sql

FROM aws.ec2.instances
WHERE region = 'us-east-1';
```

Для долгосрочного анализа аналогичный подход в StackQL - запуск этого запроса по расписанию (через cron, CI или pystackql) и добавление результатов в собственное хранилище - результат тот же, что и при ELT, но запросы в реальном времени остаются доступными для вопросов, чувствительных ко времени.
