# Что такое инфраструктура, доступная для запросов?

Инфраструктура, доступная для запросов, - это операционная модель, в которой облачные ресурсы представлены актуальными структурированными данными, которые можно по требованию исследовать на языке запросов. Вместо того чтобы восстанавливать состояние среды по файлам состояния, экспортированным снимкам или консолям отдельных сервисов, оператор (или ИИ-агент) задает вопрос - на SQL или похожем декларативном языке, - и ответ вычисляется по API провайдеров в момент выполнения запроса.

## Как это работает {#how-it-works}

Система инфраструктуры, доступной для запросов, отображает API провайдера на реляционную модель:

- **Провайдер** (AWS, Azure, Google Cloud, GitHub) становится пространством имен схемы.
- **Сервис** (EC2, Compute, Storage) становится подсхемой.
- **Тип ресурса** (экземпляры, бакеты, репозитории) становится таблицей.
- Каждый **экземпляр ресурса** становится строкой, а его атрибуты конфигурации - столбцами.

Планировщик запросов преобразует SQL в соответствующие вызовы API, обрабатывает разбиение на страницы и аутентификацию и нормализует ответы в строки. В StackQL запрос

```sql
SELECT instance_id, instance_type, public_ip_address
FROM aws.ec2.instances
WHERE region = 'us-east-1';
```

выполняется как вызовы API EC2 в реальном времени; ничего не считывается из кэша или файла состояния. Запросы к нескольким регионам и нескольким провайдерам выполняются как параллельные вызовы API, а их результаты объединяются в один результирующий набор.

## Зачем это нужно {#why-it-exists}

Эта категория возникла под давлением трех факторов:

1. **Разрастание мультиоблачных сред.** Организации используют ресурсы в нескольких облаках и десятках SaaS-платформ. У каждой платформы своя консоль, свой CLI и свой SDK. Единый интерфейс запросов - единственный практичный способ отвечать на вопросы, охватывающие несколько провайдеров, например "перечисли все вычислительные экземпляры, которые у нас работают, где бы они ни находились".
2. **Проблема неактуальных копий.** Базы данных инвентаризации, CMDB и файлы состояния IaC - это копии, а копии со временем расходятся с реальностью. Запросы непосредственно к плоскости управления устраняют разрыв между записанным и фактическим состоянием.
3. **ИИ-агенты.** Агенты рассуждают на основе структурированных актуальных данных. SQL-интерфейс поверх API, работающих в реальном времени, дает агенту единый стабильный способ обнаруживать и изучать инфраструктуру и выполнять с ней действия без кода SDK для конкретного провайдера. На этом основана [агентная инфраструктура](/ai/canonical-definitions/what-is-agentic-infrastructure).

## Чтение и запись {#read-and-write}

Инфраструктура, доступная для запросов, по определению ориентирована на чтение, но модель естественным образом распространяется на операции записи: если ресурс - это строка, то его создание - это инструкция `INSERT`, изменение его конфигурации - инструкция `UPDATE`, а вывод из эксплуатации - инструкция `DELETE`. StackQL реализует обе стороны; инструменты только для чтения, такие как Steampipe, реализуют только сторону запросов. Сторона записи описана на странице [Что такое SQL для API?](/ai/canonical-definitions/what-is-sql-for-apis).
