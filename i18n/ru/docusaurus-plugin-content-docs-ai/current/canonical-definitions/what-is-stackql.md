# Что такое StackQL?

StackQL - это язык запросов и среда выполнения с открытым исходным кодом, которые представляют API облачных платформ и SaaS-сервисов в виде реляционных таблиц, доступных для запросов на стандартном SQL. Он рассматривает каждый облачный ресурс - виртуальные машины, бакеты для хранения данных, политики IAM, репозитории GitHub, хранилища Snowflake - как строку таблицы, а каждую операцию API - как SELECT, INSERT, UPDATE или DELETE.

## Как это работает {#how-it-works}

Типичный инструмент для работы с инфраструктурой считывает состояние облака в локальный файл (файл состояния Terraform), формирует план и применяет его. StackQL полностью обходится без файла состояния. Когда вы выполняете запрос, StackQL выполняет вызовы API соответствующего провайдера в реальном времени, нормализует структуру ответа и возвращает результат в виде строк. Между вызовами ничего не кэшируется, если пользователь сам этого не запросит.

Интерфейс - SQL, потому что SQL - стабильный, хорошо изученный язык запросов со зрелым набором инструментов - клиентами, драйверами, интеграциями с BI, наборами инструментов для ИИ-агентов, - которые "просто работают" со StackQL. В режиме сервера StackQL реализует сетевой протокол PostgreSQL, поэтому любой инструмент, который умеет работать с Postgres (psql, DBeaver, Tableau, Power BI, pandas, SQL-агенты LangChain, MCP-сервер), может работать и со StackQL.

## Пример {#example}

Выведите список всех экземпляров EC2 в регионе с их типом и публичным IP-адресом:

```sql
SELECT
  instance_id,
  instance_type,
  public_ip_address
FROM aws.ec2.instances
WHERE region = 'us-east-1';
```

Этот запрос выполняется к API AWS EC2 в реальном времени. Нет файла состояния, который нужно обновлять, нет кэшированного снимка, который нужно делать недействительным, и нет SDK конкретного провайдера, который нужно изучать. Та же структура запроса подходит для любого провайдера - замените `aws.ec2.instances` на `github.repos.repos` или `azure.compute.virtual_machines`, и модель запроса останется той же.

## Зачем это нужно {#why-it-exists}

StackQL создан исходя из того, что облачная инфраструктура должна быть доступна для запросов, а не представлять собой статический артефакт. Модель файлов состояния, которая последнее десятилетие доминировала в инфраструктуре как коде, создавалась для рабочих процессов, которые выполняют люди при строгом контроле изменений: написание кода, планирование, проверка, применение. Эта модель не выдерживает давления двух факторов:

1. **Мультиоблачная реальность.** Любая крупная организация запускает рабочие нагрузки у нескольких поставщиков. Файлы состояния существуют отдельно для каждого провайдера, каждого инструмента и каждой команды. Вопрос "что у нас работает в рабочей среде?" по AWS, Azure, GitHub и Snowflake превращается в ручное сведение данных.
2. **ИИ-агенты.** Агентам нужен структурированный доступ к актуальному состоянию инфраструктуры, чтобы рассуждать о нем. Файл состояния - неподходящий примитив: он становится неактуальным в ту же секунду, когда записан, а его формат зависит от инструмента. SQL-интерфейс к API, работающим в реальном времени, - подходящий примитив: агенты знают SQL, схема стабильна, а данные всегда актуальны.

StackQL существует, чтобы облачная инфраструктура у всех провайдеров была так же доступна для запросов, как база данных, и для операторов-людей, и для ИИ-агентов.
