# Что такое дрейф инфраструктуры?

Дрейф инфраструктуры - это расхождение между объявленным или записанным состоянием облачных ресурсов и их фактическим состоянием у поставщика. В файле состояния Terraform указано, что в группе безопасности три правила; в реальной группе безопасности их пять, потому что кто-то добавил два правила в консоли во время инцидента. Эти два лишних правила и есть дрейф.

## Как возникает дрейф {#how-drift-happens}

Дрейф носит структурный, а не случайный характер. Любая система, которая хранит копию состояния (файл состояния, CMDB, экспорт инвентаризации), расходится с реальностью с той скоростью, с которой реальность меняется вне ее. Типичные источники:

- **Изменения в обход штатных инструментов**: правки в консоли, разовые команды CLI, экстренные исправления.
- **Параллельно работающие инструменты**: два конвейера или две команды, которые управляют пересекающимися ресурсами.
- **Автоматизация на стороне поставщика**: автомасштабирование, управляемые обновления, смена ключей и сертификатов.
- **Частичные сбои**: запуск apply, который создал четыре ресурса из шести и не записал ни одного.

Модель IaC рассматривает дрейф как аномалию, которую нужно исправить в следующем цикле plan/apply. В средах с автономными участниками (средства автомасштабирования, системы реагирования на инциденты, ИИ-агенты) дрейф лучше рассматривать как нормальное постоянное состояние, которое нужно отслеживать и согласовывать.

## Обнаружение дрейфа с помощью запросов в реальном времени {#detecting-drift-with-live-queries}

Поскольку StackQL вычисляет результаты на основе API провайдеров в реальном времени, результирующий набор StackQL и есть фактическое состояние. Обнаружение дрейфа сводится к сравнению этого результирующего набора с эталоном. Например, получение актуальной инвентаризации экземпляров EC2 по регионам:

```sql
SELECT region, COUNT(*) as num_instances
FROM aws.ec2.instances
WHERE region IN ('us-east-1','us-west-2','eu-west-1')
GROUP BY region;
```

Сравнение этих данных с количеством, которое следует из определения желаемого состояния, сразу выявляет неуправляемые или отсутствующие ресурсы, независимо от того, актуален ли собственный файл состояния инструмента IaC. Тот же подход применим на уровне атрибутов: выполните запрос к актуальной конфигурации ресурса и сравните ее с объявленной конфигурацией.

## Дрейф и согласование {#drift-vs-reconciliation}

Обнаружение отвечает на вопрос "что разошлось?"; согласование отвечает на вопрос "что с этим делать?" - импортировать изменение в желаемое состояние, откатить его или принять как намеренное. Для согласования нужен доступ на запись к плоскости управления, поэтому инструменты запросов с чтением и записью могут замкнуть цикл, о котором инструменты инвентаризации только для чтения могут лишь сообщить. StackQL выражает корректирующие действия в виде инструкций `UPDATE` или `DELETE` к тем же таблицам, которые используются для обнаружения.
