# Что такое SQL для API?

SQL для API - это шаблон проектирования, который проецирует операции API на реляционную семантику: операции получения списка и получения объекта становятся инструкциями `SELECT`, операции создания - инструкциями `INSERT`, операции изменения - инструкциями `UPDATE` или `REPLACE`, а операции удаления - инструкциями `DELETE`. Объекты ответа API становятся строками, а их атрибуты - столбцами. Этот шаблон дает любому REST или RPC API удобство работы с базой данных и не требует от поставщика API никаких изменений.

## Как это работает {#how-it-works}

Отображение выполняется механически, и именно поэтому его можно обобщить:

| Понятие API | Реляционное понятие |
|---|---|
| Провайдер (AWS, GitHub) | Пространство имен схемы |
| Сервис (EC2, repos) | Подсхема |
| Коллекция ресурсов | Таблица |
| Операция получения списка / получения объекта | Метод `SELECT` |
| Операция создания | Метод `INSERT` |
| Операция patch / put | Метод `UPDATE` / `REPLACE` |
| Операция удаления | Метод `DELETE` |
| Другие действия жизненного цикла (запуск, остановка, перезагрузка) | Метод `EXEC` |
| Обязательные параметры пути или строки запроса | Обязательные предикаты предложения `WHERE` |
| Поля тела запроса | Столбцы вставки и обновления с префиксом `data__` |

В StackQL это отображение генерируется из расширенных спецификаций OpenAPI, которые хранятся в открытом [реестре провайдеров StackQL](https://github.com/stackql/stackql-provider-registry). Обязательные параметры API можно обнаружить во время выполнения: инструкция `SHOW METHODS IN aws.ec2.instances` возвращает глагол SQL и обязательные параметры каждого метода, поэтому человек или ИИ-агент может составить правильный запрос, не читая документацию провайдера.

## Пример {#example}

Чтение - это инструкция `SELECT`, предложение `WHERE` которой содержит обязательные параметры API:

```sql
SELECT name, language, stargazers_count
FROM github.repos.repos
WHERE org = 'stackql';
```

Создание - это инструкция `INSERT`, столбцы которой содержат тело запроса (с префиксом `data__`) и параметры маршрутизации:

```sql
INSERT INTO google.storage.buckets(
  project,
  data__name,
  data__location
)
SELECT
  'my-project',
  'my-new-bucket',
  'US';
```

Инструкция `SHOW INSERT INTO google.storage.buckets` механически генерирует этот шаблон инструкции, включая все поля, доступные для записи.

## Зачем это нужно {#why-it-exists}

SQL - самый распространенный из существующих языков запросов, и за пятьдесят лет вокруг него сложился обширный набор инструментов: драйверы, ORM, платформы BI, блокноты и - что приобретает растущее значение - обучающие данные LLM. Любая распространенная ИИ-модель уже умеет грамотно читать и писать SQL. Проекция API в SQL означает, что весь этот инструментарий и возможности моделей сразу применимы к любому API. Альтернатива - отдельный SDK для каждого провайдера на каждом языке - умножает работу по интеграции и не дает агентам ничего пригодного для повторного использования. Подробнее этот аргумент изложен на странице [Почему SQL хорошо подходит в качестве интерфейса к облачным API](/ai/concepts/why-sql-is-a-strong-interface-for-cloud-apis).
