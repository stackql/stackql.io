Повторно загружает в среду процесса сервера файл в формате dotenv, указанный флагом [`--env.file`](/command-line-usage/global-flags), а затем сообщает статус определения учетных данных для каждого провайдера.  Это решает проблему среды, зафиксированной при запуске: учетные данные, записанные на диск или смененные посреди сеанса, попадают в работающий сервер без перезапуска.

Файл env накладывается на среду процесса, а не заменяет ее: при определении учетных данных всегда читается текущая среда процесса в момент запроса, поэтому переменные, заданные уже при запуске (из оболочки или из блока `env` клиента), продолжают работать как с флагом `--env.file`, так и без него.  При повторной загрузке записываются только ключи, которые есть в файле и имеют непустые значения, и значение переменной никогда не сбрасывается, поэтому неудачная или частичная повторная загрузка сохраняет учетные данные, которые работали ранее.

Значения секретов никогда не возвращаются, не записываются в журнал и не попадают в журнал аудита - инструмент сообщает только имена переменных и их статусы.  Если флаг `--env.file` не настроен, инструмент сводится к простой проверке статуса.  Когда запрос завершается ошибкой при определении учетных данных, ошибка MCP содержит подсказку, которая предлагает агенту вызвать инструмент `reload_credentials` и повторить попытку, поэтому агентные клиенты восстанавливаются самостоятельно.

:::note

Доступно в выпусках StackQL после `v0.10.542`.

:::

## Входные данные {#inputs}

| Аргумент | Обязательный | Описание |
|--|--|--|
|`provider`|Нет|Ограничивает отчет о статусе одним провайдером.  Если аргумент не указан, в отчет входит каждый провайдер.|

* * *

## Выходные данные {#output}

| Средство отображения | Форма |
|--|--|
| Таблица | Результат загрузки файла env и по одной строке на каждый провайдер со статусом определения учетных данных |

<br/>

Структурированная полезная нагрузка содержит:

| Поле | Описание |
|--|--|
|`env_file`|Настроенный путь `--env.file` (пустой, если путь не настроен).|
|`env_file_sourced`|`true`, если файл найден и загружен при этом вызове.|
|`sourced_vars`|Имена переменных среды, заданных из файла - только имена, никогда не значения.|
|`providers`|Одна строка на каждый провайдер (см. ниже).|

<br/>

Каждая строка `providers` содержит:

| Столбец | Описание |
|--|--|
|`provider`|Имя провайдера.|
|`auth_type`|Тип аутентификации, настроенный для провайдера.|
|`sourced_from`|Источник, из которого определены учетные данные, например `env:OKTA_SECRET_KEY`, `file:/path/key.json`, `inline` или `none`.|
|`status`|`ok`, `unresolved` или `not_checked`.|
|`detail`|Текст ошибки при статусе `unresolved`.|

<br/>

Типы аутентификации, которые выполняют аутентификацию вне пути байтов учетных данных (интерактивный gcloud, Azure CLI, oauth2 client credentials, цепочки принятия ролей, подпись OCI, null), сообщают статус `not_checked`.

* * *

## Контроль {#gating}

Разрешено во всех режимах сервера, включая режим `read_only` - инструмент ничего не изменяет, кроме собственной среды процесса сервера.

Не поддерживается в режиме бэкенда `reverse_proxy`: запросы выполняются в удаленном процессе сервера stackql, поэтому инструмент возвращает ошибку, которая предлагает пользователю повторно загрузить учетные данные на базовом сервере.

## Пример {#example}

Попробуйте этот промпт в любом MCP-клиенте, в котором зарегистрирован MCP-сервер StackQL (запущенный с флагом `--env.file`):

```
My okta query failed with a credential error - I've just written the key
to the credentials file.  Reload credentials and retry the query.
```
