Ищет в [Query Library StackQL](pathname:///docs/query-library/) шаблоны, соответствующие намерению, сформулированному на естественном языке. Обращайтесь к нему, прежде чем составлять SQL с нуля, а затем передайте `id` из результата в [`query_library_get`](/mcp/query_library_get), чтобы просмотреть шаблон и проверить его параметры.

Инструмент только получает содержимое библиотеки. Он не выполняет SQL, не вызывает облачные API и не требует учетных данных провайдера.

См. также:
[[ Обзор MCP ]](/command-line-usage/mcp) [[ `query_library_get` ]](/mcp/query_library_get) [[ `validate_select_query` ]](/mcp/validate_select_query)

## Входные данные {#inputs}

| Аргумент | Обязательный | Описание |
|--|--|--|
|`intent`|Да|Описание задачи на естественном языке.|
|`provider`|Нет|Фильтр по провайдеру, например `aws`.|
|`service`|Нет|Фильтр по сервису, например `s3`.|
|`tags`|Нет|Массив тегов. Запись должна соответствовать каждому переданному тегу.|
|`include_mutations`|Нет|Включать шаблоны изменения данных. По умолчанию: `false`; игнорируется в режиме `read_only`, в котором записи изменения данных всегда исключаются.|
|`limit`|Нет|Максимальное число результатов. По умолчанию: `5`, если значение не указано или не положительное; не более `20`.|
|`format`|Нет|Формат текстового отображения: `markdown` или `json`. Если не указан, используется настройка отображения сервера (по умолчанию `markdown`).|

* * *

## Выходные данные {#output}

Текстовый вывод по умолчанию - ранжированная таблица со столбцами `id`, `title`, `mutation`, `required_params` и `score`, за которой следуют ссылка на источник и рекомендации при отсутствии совпадений, если они есть. Структурированная полезная нагрузка содержит:

| Поле | Описание |
|--|--|
|`hits`|Ранжированные записи с полями `id`, `title`, необязательным `description`, `providers`, `services` и `required_params`, а также `mutation` и `score`. Затем вызовите `query_library_get`, чтобы получить полные объявления параметров.|
|`miss`|`true`, если совпадений нет или наивысшая оценка ниже порога совпадения. При этом ближайшие совпадения с низкой оценкой могут быть возвращены.|
|`guidance`|При отсутствии совпадений направляет агента к указаниям сервера, инструментам обнаружения и `validate_select_query` для составления запроса.|
|`source_tier`|Источник содержимого: `primary`, `fallback` или `snapshot`.|
|`source_url`|URL-адрес или встроенный путь использованного каталога для ссылки на источник.|
|`stale`|Если `true`, содержимое было выдано из кэша или встроенного снимка после ошибки получения данных.|

Устаревшие записи исключаются. Сервер кэширует каталог и может переключаться с размещенной библиотеки на ее исходные файлы в GitHub и встроенный снимок.

* * *

## Контроль {#gating}

Разрешено во всех режимах сервера с учетом настроенного списка разрешенных инструментов. Подтверждение и учетные данные провайдера не требуются. Поиск шаблонов изменения данных не дает разрешения на их выполнение.

## Пример {#example}

Аргументы инструмента:

```json
{
  "intent": "List S3 bucket names and regions",
  "provider": "aws",
  "service": "s3",
  "limit": 5
}
```

Используйте `id` из `hits`, например `aws/s3/buckets-list`, с инструментом [`query_library_get`](/mcp/query_library_get). Если `miss` имеет значение `true`, изучите ближайшие шаблоны в качестве ориентира или используйте [`list_methods`](/mcp/list_methods) и [`describe_method`](/mcp/describe_method), прежде чем составлять SQL.
