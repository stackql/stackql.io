Получает запись [Query Library](pathname:///docs/query-library/) по идентификатору `id`, который вернул инструмент [`query_library_search`](/mcp/query_library_search).

Если `params` не указан или пуст, инструмент возвращает исходный шаблон, объявления параметров и примечания. Если передан непустой объект `params`, сервер проверяет значения и подставляет их в шаблон. SQL возвращается, только если формирование прошло успешно. Модели не нужно подставлять значения самостоятельно.

Этот инструмент не выполняет SQL и не проверяет облачные учетные данные. Его проверка параметров отличается от проверки инструментом [`validate_select_query`](/mcp/validate_select_query), который выполняет синтаксический анализ и планирование инструкции `SELECT` для установленного провайдера.

## Входные данные {#inputs}

| Аргумент | Обязательный | Описание |
|--|--|--|
|`id`|Да|Идентификатор запроса из результатов поиска, например `aws/s3/buckets-list`.|
|`params`|Нет|Объект, сопоставляющий объявленные имена параметров со значениями. Не указывайте его или передайте `{}`, чтобы просмотреть шаблон без формирования SQL.|
|`format`|Нет|Формат текстового отображения: `markdown` или `json`. Если не указан, используется настройка отображения сервера (по умолчанию `markdown`).|

Неизвестные параметры отклоняются. Обязательные параметры без переданных значений или значений по умолчанию перечисляются в `missing_params`. Переданные значения проверяются на соответствие объявленным типам и ограничениям; заполнители без подставленных значений считаются ошибками.

* * *

## Выходные данные {#output}

Текстовый вывод по умолчанию - блок KV с идентификационными данными, признаком изменения данных, следующим инструментом, признаком допустимости, ссылками на источники, а также шаблоном, сформированным SQL или ошибками, если они есть. Чтобы получить полные метаданные, используйте структурированную полезную нагрузку или `format: "json"`:

| Поле | Описание |
|--|--|
|`id`, `title`, `description`|Идентификационные данные записи и краткое описание.|
|`mutation`, `verb`|Изменяет ли запись ресурсы и, если объявлен, тип ее операции (`select`, `mutation` или `lifecycle`).|
|`next_tool`|Инструмент выполнения для записи: `run_select_query`, `run_mutation_query` или `run_lifecycle_operation`. При получении записи он не вызывается.|
|`params`|Объявления параметров с именами, типами, признаками обязательности, а также значениями по умолчанию, описаниями, примерами, перечислениями или шаблонами регулярных выражений, если они есть.|
|`template`, `notes`|Исходный шаблон и примечания автора; возвращаются, если `params` не указан или пуст.|
|`rendered`, `valid`|Была ли выполнена попытка формирования и успешна ли она. Оба поля имеют значение `false` при просмотре исходного шаблона.|
|`sql`|Сформированный SQL; присутствует только после успешного формирования.|
|`missing_params`, `unknown_params`, `errors`|Подробности проверки, если формирование не удалось. Не выполняйте SQL, пока эти проблемы не устранены.|
|`auth`, `permissions`|Если объявлены, переменные среды с учетными данными и собственные разрешения провайдера, необходимые для выполнения. Для самого получения не требуется ни то, ни другое.|
|`cost`, `outputs`, `related`|Если объявлены, подсказки о fan-out и затратах, описания столбцов результата и идентификаторы связанных записей.|
|`doc_url`|Страница библиотеки, удобная для чтения человеком.|
|`source_tier`, `source_url`, `stale`|Происхождение содержимого: `primary`, `fallback` или `snapshot`, его URL-адрес или встроенный путь, а также признак того, было ли содержимое выдано из кэша или снимка после ошибки получения данных.|

Для неизвестного или неправильно сформированного идентификатора возвращается ошибка. Чтобы найти допустимые идентификаторы, используйте `query_library_search`.

## Контроль {#gating}

Разрешено во всех режимах сервера с учетом настроенного списка разрешенных инструментов. Получение или формирование шаблона изменения данных или операции жизненного цикла не имеет побочных эффектов в облаке и не требует подтверждения. Выполнение возвращенного SQL - отдельный вызов, который контролируется [режимом](/command-line-usage/mcp#server-modes) сервера.

## Пример {#example}

Сначала просмотрите запись:

```json
{
  "id": "aws/s3/buckets-list"
}
```

Затем передайте обязательный для нее регион маршрутизации:

```json
{
  "id": "aws/s3/buckets-list",
  "params": {
    "region": "us-east-1"
  }
}
```

Проверив `rendered` и `valid`, проверьте возвращенную инструкцию `SELECT` с помощью [`validate_select_query`](/mcp/validate_select_query). Выполните ее инструментом, указанным в `next_tool`: передайте возвращенное значение `sql` и задайте для `source` значение `id` записи библиотеки, чтобы указать источник. Во время выполнения требуются учетные данные и разрешения провайдера.
