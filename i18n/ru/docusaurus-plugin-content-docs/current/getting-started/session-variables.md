Переменные сеанса - это скалярные значения, которые хранит текущий сеанс и на которые ссылаются последующие инструкции.  Они доступны в StackQL `v1.0` и более поздних версиях и работают в интерактивной оболочке, в скриптах `exec`, через сетевой протокол PostgreSQL и через MCP-сервер.

Переменные сеанса отличаются от переменных шаблонизации, описанных на странице [Использование переменных](/getting-started/variables).  Переменные шаблонизации передаются команде `stackql exec` через `--iqldata` и `--var` и подставляются в текст скрипта до его синтаксического анализа.  Значения переменных сеанса определяются внутри уже проанализированной инструкции, сохраняют свой тип и могут изменяться между инструкциями.

## Задание и удаление переменных {#setting-and-removing-variables}

Инструкция [`SET`](/language-spec/set) присваивает строковое значение, число, логическое значение или `null`.  Инструкция [`UNSET`](/language-spec/unset) удаляет переменную; `SET name = DEFAULT` делает то же самое.  Явное значение `null` - это сохраненное значение, а не сброс.

```sql
SET region = 'ap-southeast-2';
SET minimum_count = 3;
SET enabled = true;
SET optional_value = null;
UNSET region;
```

Массивы и объекты не являются скалярными значениями.  Чтобы хранить JSON-документ, сохраните его как строку:

```sql
SET "providers.saved" = '{"provider":"aws","tenancy":"production"}';
```

## Разыменование переменной {#dereferencing-a-variable}

Используйте `$name` без кавычек в любой позиции, где допускается выражение.  Строки экранируются как SQL-литералы; числа, логические значения и `null` сохраняют свой тип.  `'$name'` в одинарных кавычках - это буквальный текст `$name`, а не разыменование.  Ссылка на несуществующую переменную приводит к ошибке еще до отправки какого-либо запроса к провайдеру.

Полученные значения можно использовать в обычных SQL-выражениях, включая `CAST`, `CONVERT`, конкатенацию с помощью `||` и вызовы функций:

```sql
SET some_id = 42;
SET suffix = 'East';

SELECT CAST($some_id AS TEXT) AS id_text,
       CONVERT($some_id, TEXT) || '-' || lower($suffix) AS label,
       md5(lower(CONVERT($some_id, TEXT) || '-' || $suffix)) AS digest,
       '$some_id' AS literal_text;
```

Присваивание принимает только скалярные литералы или прямые ссылки; применяйте преобразования и другие выражения там, где переменная используется, а не в инструкции `SET`.

## Переменные в предикатах {#variables-in-predicates}

Значение переменной в предложении `WHERE` определяется до планирования инструкции, поэтому оно передается в API провайдера точно так же, как литерал.  Следовательно, обязательные параметры можно передавать через переменные:

```sql
SET project = 'stackql-demo';
SET zone = 'australia-southeast1-a';

SELECT name, status
FROM google.compute.instances
WHERE project = $project AND zone = $zone;
```

Типизированные значения сравниваются с учетом их типа.  `WHERE active = $enabled` при `SET enabled = false` фильтрует по логическому значению, а форму `WHERE id = CAST($some_id AS TEXT)` следует использовать, когда столбец провайдера строковый, а переменная - число.

## Переменные как имена объектов {#variables-as-object-names}

Переменные могут задавать не только значения, но и имена отношений и столбцов.  Имена преобразуются в идентификаторы в проанализированной инструкции и никогда не вставляются в текст SQL, поэтому значение, которое содержит инструкцию, пустое или не является строкой, отклоняется еще до какого-либо обращения к провайдеру.

| Позиция | Форма |
|--|--|
| Предложение `FROM` | `FROM $relation_name` или по компонентам: `FROM $provider.$service.$resource` |
| Столбец в выражении | `IDENTIFIER($column_name)`, см. [`IDENTIFIER`](/language-spec/functions/general/identifier) |
| Псевдоним столбца или таблицы | `AS "$alias_name"` |
| `ORDER BY` | `ORDER BY IDENTIFIER($column_name)` |
| `LIMIT` | `LIMIT $row_count` |
| Имена столбцов в DDL, списки столбцов `INSERT`, цели `UPDATE` | форма `"$name"` в двойных кавычках |
<br/>

```sql
SET relation_name = 'aws.s3.buckets';
SET column_name = 'name';
SET output_name = 'bucket';
SET row_count = 10;

SELECT IDENTIFIER($column_name) AS "$output_name"
FROM $relation_name
WHERE region = 'ap-southeast-2'
ORDER BY IDENTIFIER($column_name)
LIMIT $row_count;
```

Соединения, CTE и вложенные запросы определяют значения своих переменных отношений так же.  Значения отношений с точками содержат не более четырех компонентов.  Переменные не являются произвольными фрагментами SQL: подставить ключевое слово, список столбцов через запятую или целое предложение `WHERE` нельзя.

## Область действия и изоляция {#scope-and-isolation}

Переменные принадлежат сеансу, который их задал.  У отдельных подключений к серверу `stackql srv` отдельные переменные, как и у отдельных вызовов `exec`.  Каждый MCP-запрос - это отдельный сеанс, поэтому `SET` и использующий переменную запрос нужно отправлять в одном пакете инструкций.  Новые сеансы начинаются без переменных.

Сеанс - единственная область действия.  `SET SESSION` и `UNSET SESSION` принимаются и означают ровно то же, что `SET` и `UNSET`; это ключевое слово нужно для скриптов, которые должны читаться так же, как в базах данных, где настройки сеанса и глобальные настройки различаются.  `GLOBAL` отклоняется, так как общего для сеансов состояния нет.

Подготовленные инструкции определяют значения переменных при выполнении, а не при подготовке, и план, содержащий привязанные значения сеанса, не используется повторно между выполнениями.

Если включено [управление доступом](/command-line-usage/access-management), для чтения переменной требуется разрешение `session/variables:read`, а для ее задания или сброса - `session/config:write`.  Определение переменной как имени объекта не предоставляет никаких разрешений на этот объект; полученное отношение, как обычно, авторизуется перед выполнением.
