# Асинхронные межрегиональные запросы в StackQL

В этом руководстве мы покажем мощную возможность StackQL: выполнение запросов к ресурсам в нескольких регионах AWS и их агрегирование.  Для этого отправляется множество запросов к API на разные конечные точки, и эти запросы выполняются асинхронно.  Для пользователя это происходит незаметно и прозрачно.  

> StackQL - это мощный инструмент разработчика, который позволяет выполнять запросы к облачной инфраструктуре и ресурсам и развертывать их с использованием синтаксиса SQL.  

Проверено с <span class="tutorial_tested_on">встроенный SQL-бэкенд</span> <span class="tutorial_tested_on">SQL-бэкенд postgres</span> <span class="tutorial_tested_on">macos</span> <span class="tutorial_tested_on">linux</span> <span class="tutorial_tested_on">powershell</span>

## Общие сведения о регионах и ресурсах AWS {#understanding-aws-regions-and-resources}

Ресурсы AWS размещаются во множестве местоположений по всему миру.  Эти местоположения состоят из регионов и зон доступности, которые позволяют пользователям размещать экземпляры и хранить данные в разных местах.

## Проблема с регионами AWS... {#the-problem-with-aws-regions}

При работе с AWS важно понимать, что AWS Management Console показывает ресурсы в пределах региона и позволяет пользователям взаимодействовать с ресурсами и управлять ими только в одном конкретном регионе за раз.  Аналогично команды AWS Command Line Interface (CLI) и наборы средств разработки программного обеспечения (SDK) используют регион как точку входа для операций, поэтому для выполнения команд или запуска программ необходимо указать регион.  

> Региональная структура облачных сервисов создает сложности, когда ресурсы охватывают несколько регионов.  Кроме того, при нарушениях безопасности, включая эксплойты для майнинга криптовалюты, часто используются ресурсы в разных местах, за пределами основного региона, который обычно используют организации.

## Указание регионов в запросах StackQL {#specifying-regions-in-stackql-queries}

С помощью StackQL вы можете указывать регионы, чтобы обращаться к ресурсам в разных географических местоположениях.  Это особенно полезно для управления ресурсами, распределенными по всему миру.

### Пример: вывод списка экземпляров EC2 в нескольких регионах {#example-listing-ec2-instances-across-multiple-regions}

```sql
SELECT instance_id, region
FROM aws.ec2.instances
WHERE region IN ('us-east-1', 'eu-west-1');
```

Этот запрос возвращает список экземпляров EC2 из регионов `us-east-1` (Северная Вирджиния) и `eu-west-1` (Ирландия) и показывает, как StackQL может получать данные из разных регионов одним запросом.  Это можно использовать и в агрегатных запросах, например:  

```sql
SELECT region, COUNT(*) as num_functions
FROM aws.lambda.functions
WHERE region IN (
  'us-east-1','us-east-2','us-west-1','us-west-2',
  'ap-south-1','ap-northeast-3','ap-northeast-2',
  'ap-southeast-1','ap-southeast-2','ap-northeast-1',
  'ca-central-1','eu-central-1','eu-west-1',
  'eu-west-2','eu-west-3','eu-north-1','sa-east-1')
GROUP BY region;
```

## Возможности асинхронных запросов {#the-power-of-asynchronous-queries}

StackQL выполняет эти межрегиональные запросы асинхронно и отправляет в AWS несколько параллельных запросов к API.  Это обеспечивает эффективное получение данных без ожидания завершения запроса к одному региону перед переходом к следующему.

## Заключение {#conclusion}

Асинхронные межрегиональные запросы в StackQL - надежный и эффективный способ управления ресурсами AWS в разных географических местоположениях.  Благодаря синтаксису этих запросов, похожему на SQL, StackQL упрощает сложные задачи управления облаком, что делает его незаменимым инструментом для разработчиков и администраторов облачных сред, стремящихся оптимизировать свою инфраструктуру AWS.
