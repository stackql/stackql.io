Удаляет переменную сеанса или сбрасывает конфигурацию времени выполнения, заданную с помощью [`SET`](/language-spec/set) для текущего сеанса.  Доступно в StackQL `v1.0` и более поздних версиях.

См. также:  
[[` SET `]](/language-spec/set) [[ Переменные сеанса ]](/getting-started/session-variables) [[ Сеансы провайдеров ]](/getting-started/provider-sessions)

## Синтаксис {#syntax}

*unsetStatement::=*

&nbsp;  
&nbsp;  

```sql
UNSET [ SESSION ] <target> [, <target> ...];
```

__*target*__  
Любая цель, которую принимает `SET`: имя переменной, простое или в двойных кавычках, либо путь конфигурации в двойных кавычках, начинающийся со знака доллара.

__*SESSION*__  
Необязательное ключевое слово, обозначающее единственную существующую область: `UNSET SESSION name` и `UNSET name` - одна и та же инструкция, поскольку каждая переменная и каждый параметр конфигурации принадлежат текущему сеансу.  `UNSET GLOBAL` отклоняется с ошибкой `configuration scope "global" is not supported; use SESSION`.

`UNSET name` эквивалентно `SET name = DEFAULT`.  Цели в одном списке удаляются по порядку, и удаление имени, которое не задано, не считается ошибкой.  Разыменование переменной после сброса ее значения завершается ошибкой до того, как будет выполнен какой-либо запрос к провайдеру.

| Цель | Действие |
|--|--|
| `name` | Удаляет переменную сеанса. |
| `"$.auth.<provider>.<field>"` | Удаляет это поле из контекста аутентификации провайдера в сеансе.  Значение, действовавшее до переопределения, не восстанавливается. |
| `"$.providers.<alias>"` | Удаляет привязку псевдонима провайдера. |
| `"$.secrets.<name>"` | Удаляет секрет из хранилища сеанса.  Для постоянного хранилища ОС при этом удаляется сохраненное значение. |
| `"$.secret_store"` | Отменяет текущую привязку хранилища и начинает работу с пустой памятью сеанса.  Значения, уже сохраненные в хранилище ОС, не удаляются. |

## Примеры {#examples}

### Удаление переменной {#remove-a-variable}

Переменная удаляется из сеанса, поэтому закомментированный запрос завершается ошибкой `variable "$region" is not defined`, а не выполняется с неактуальным или пустым значением.  Чтобы снова использовать это имя, задайте его повторно.

```sql
SET region = 'ap-southeast-2';
UNSET region;

/*
SELECT name FROM aws.s3.buckets WHERE region = $region;
-- FAILS with variable "$region" is not defined
*/
```

### Удаление нескольких целей {#remove-several-targets}

Одна инструкция может удалить переменные и пути конфигурации вместе, и цели обрабатываются по порядку.  Здесь в одном списке удаляются простая переменная, переменная с именем, содержащим точки, и переопределение учетных данных.

```sql
UNSET region, "providers.saved", "$.auth.github.password_var";
```

### Явное указание области сеанса {#make-the-session-scope-explicit}

Эти две инструкции делают одно и то же: `SESSION` обозначает единственную существующую область.  Явная форма подходит для скриптов, которые также выполняются в базах данных, различающих состояние сеанса и глобальное состояние.  Закомментированная инструкция завершается ошибкой, поскольку общего состояния не существует.

```sql
UNSET region;
UNSET SESSION region;

/*
UNSET GLOBAL region;
-- FAILS with configuration scope "global" is not supported; use SESSION
*/
```

### Сброс переопределения учетных данных {#clear-a-credential-override}

Поле, ранее заданное с помощью `SET "$.auth.github.password_var"`, удаляется из контекста аутентификации провайдера GitHub в сеансе, а остальные поля этого контекста не затрагиваются.  Значение, действовавшее до переопределения, не восстанавливается, поэтому задайте поле снова, если оно по-прежнему нужно провайдеру.

```sql
UNSET "$.auth.github.password_var";
```

### Удаление псевдонима провайдера и его секрета {#remove-a-provider-alias-and-its-secret}

Псевдоним `production` был привязан с помощью `SET "$.providers.production"` и через `auth_secret` ссылается на секрет, хранящийся в `$.secrets.production`.  Удаление обоих в одной инструкции снимает привязку, так что `production.s3.buckets` больше не является допустимым отношением, и удаляет секрет из хранилища сеанса.  `SESSION` здесь, как и везде, необязательно.

```sql
UNSET SESSION "$.providers.production", "$.secrets.production";
```
