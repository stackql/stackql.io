Используется для вывода списка элементов коллекции, например всех сервисов, доступных в провайдере, или всех ресурсов, доступных в определенном сервисе. Также показывает версию, участников и программные зависимости запущенного двоичного файла StackQL.

См. также:  
[[ Иерархия ресурсов StackQL ]](/getting-started/resource-hierarchy)

* * * 

## Синтаксис {#syntax}

*showStatement::=*

<RailroadDiagram 
type="show"
/>

&nbsp;  
&nbsp;  

```sql
SHOW [ EXTENDED ]
{ PROVIDERS | SERVICES | RESOURCES | METHODS }
[ { IN | FROM } { <provider> | <service> | <resource> } ]
[ { LIKE '<pattern>' | WHERE <expression> } ];

SHOW [ EXTENDED ] INSERT INTO <resource>;
SHOW [ EXTENDED ] VERSION;
SHOW [ EXTENDED ] CONTRIBUTORS;
SHOW [ EXTENDED ] DEPENDENCIES [ LIKE '<pattern>' ];
```

`VERSION`, `CONTRIBUTORS` и `DEPENDENCIES` не требуют настройки провайдеров или аутентификации. `DEPENDENCIES` поддерживает только необязательное предложение `LIKE`; `IN`, `FROM`, `WHERE` и `LIMIT` не поддерживаются.

### Генерация шаблона `INSERT` с помощью команды `SHOW INSERT` {#generating-an-insert-template-using-the-show-insert-command}

Команду `SHOW` можно использовать для генерации шаблонов инструкций `INSERT`, как показано здесь:

```sql
SHOW INSERT INTO google.compute.addresses;
```
<details>
<summary><em><strong>Возвращает:</strong></em></summary>

```sql
INSERT INTO google.compute.addresses(
  project,
  region,
  data__address,
  data__addressType,
  data__description,
  data__ipVersion,
  data__name,
  data__network,
  data__networkTier,
  data__prefixLength,
  data__purpose,
  data__subnetwork
)
SELECT
  '{{ .values.project }}',
  '{{ .values.region }}',
  '{{ .values.data__address }}',
  '{{ .values.data__addressType }}',
  '{{ .values.data__description }}',
  '{{ .values.data__ipVersion }}',
  '{{ .values.data__name }}',
  '{{ .values.data__network }}',
  '{{ .values.data__networkTier }}',
   {{ .values.data__prefixLength }},
  '{{ .values.data__purpose }}',
  '{{ .values.data__subnetwork }}'
```

</details>

> Возвращаемые поля можно ограничить только теми, которые требует провайдер; примеры см. на странице [__Создание шаблонов инфраструктуры__](/getting-started/templating).

> Затем этот шаблон можно использовать вместе с файлом данных `json` или `jsonnet`, чтобы передавать значения во время выполнения; подробнее см. [__Использование переменных__](/getting-started/variables).

### Просмотр версии StackQL {#show-the-stackql-version}

Возвращает версию запущенного процесса StackQL. Полезно в режимах shell, exec и сервера с сетевым протоколом Postgres, когда нужно убедиться, какая сборка отвечает на запросы. Те же сведения также доступны через MCP-инструмент `server_info`.

```sql
-- Returns the version of the running StackQL process
SHOW VERSION;
```
<details>
<summary><em><strong>Возвращает:</strong></em></summary>

```
|---------|
| version |
|---------|
| 1.0.888 |
|---------|
```

</details>

Используйте необязательное ключевое слово `EXTENDED`, чтобы также получить коммит git, метку времени сборки и платформу сборки:

```sql
-- Returns version plus build provenance
SHOW EXTENDED VERSION;
```
<details>
<summary><em><strong>Возвращает:</strong></em></summary>

```
|---------|---------|----------------------|----------|
| version | commit  |      build_date      | platform |
|---------|---------|----------------------|----------|
| 1.0.888 | f7b4116 | 2026-11-05T00:26:03Z | Windows  |
|---------|---------|----------------------|----------|
```

</details>

> Инструкция `SHOW VERSION` не требует настройки провайдеров, реестра или аутентификации, и ее можно безопасно выполнять в любом сеансе.

### Вывод списка участников StackQL {#list-stackql-contributors}

Возвращает рейтинг участников, встроенный в запущенный двоичный файл StackQL. Снимок отмечает участников GitHub, которые являются людьми и поставили звезду репозиторию StackQL, и упорядочивает их по числу вкладов, от наибольшего к наименьшему. Он фиксирован для каждой сборки и не выполняет запросов к GitHub во время работы.

```sql
SHOW CONTRIBUTORS;
SHOW EXTENDED CONTRIBUTORS;
```

| Столбец | Описание |
| --- | --- |
| `contributor` | Имя пользователя GitHub |
| `contributions` | Число вкладов, записанное в снимке; выводится с `EXTENDED` |

### Вывод списка программных зависимостей двоичного файла {#list-the-binarys-software-dependencies}

Возвращает инвентаризацию модулей Go, включенных в запущенный исполняемый файл StackQL, без доступа к сети. Это облегченный перечень компонентов программного обеспечения (SBOM) для двоичного файла, к которому пользователи и агенты могут выполнять запросы во время работы. Он включает прямые и транзитивные зависимости Go; установленные определения провайдеров, отдельные оболочки, инструменты CI, модули только для тестирования, образы контейнеров и пакеты операционной системы в него не входят.

```sql
SHOW DEPENDENCIES;
SHOW EXTENDED DEPENDENCIES;
```

Столбцы по умолчанию: `name`, `version`, `license` и `description`. `EXTENDED` добавляет остальные столбцы, перечисленные ниже, не меняя набор возвращаемых строк.

| Столбец | Описание |
| --- | --- |
| `name` | Действующий путь модуля Go; если применяется замена модуля Go, используется путь замены |
| `version` | Точная версия модуля, включая версии предварительных выпусков и псевдоверсии |
| `license` | Обнаруженный идентификатор лицензии; `UNKNOWN`, если лицензия не определена или неоднозначна |
| `description` | Описание компонента, если оно доступно |
| `source_url` | URL-адрес репозитория с исходным кодом; выводится с `EXTENDED` |
| `license_url` | URL-адрес файла лицензии, закрепленный за тегом модуля или ревизией исходного кода; выводится с `EXTENDED` |
| `purl` | Package URL, идентифицирующий модуль и версию; выводится с `EXTENDED` |
| `checksum` | Контрольная сумма модуля Go с префиксом `h1:`, а не дайджест SHA-256 исполняемого файла или архива; выводится с `EXTENDED` |
| `original_name` | Изначально запрошенный путь модуля, если применяется замена; выводится с `EXTENDED` |
| `original_version` | Изначально запрошенная версия, если применяется замена; выводится с `EXTENDED` |

Строки сортируются по действующему имени модуля, затем по версии. Для замен используются версия, контрольная сумма и атрибуция заменяющего модуля. Для модулей без замен `original_name` и `original_version` имеют значение `NULL`. Другие недоступные метаданные также имеют значение `NULL`, за исключением неопределенных лицензий, для которых выводится `UNKNOWN`. Замены на пути локальной файловой системы не получают вымышленных версий, URL-адресов или контрольных сумм.

Используйте `LIKE` для поиска по действующему имени модуля, изначальному имени модуля или описанию:

```sql
SHOW DEPENDENCIES LIKE '%stackql%';
SHOW EXTENDED DEPENDENCIES LIKE '%vitess%';
SHOW EXTENDED DEPENDENCIES LIKE 'github.com/chzyer/readline';
```

Сопоставление выполняется без учета регистра. `%` соответствует нулю или более символам, а `_` - ровно одному символу. Поиск по столбцам лицензии и версии не выполняется. Удваивайте одинарную кавычку внутри строкового литерала SQL; после декодирования строки SQL обратные косые черты воспринимаются буквально и не экранируют подстановочные знаки `LIKE`.

Если ни один модуль не соответствует шаблону, результат содержит ноль строк. Вывод CSV сохраняет заголовки столбцов, клиенты сетевого протокола PostgreSQL сохраняют метаданные столбцов, а вывод JSON равен `null`.

Инвентаризация объединяет метаданные, встроенные во время сборки, со сведениями о сборке Go исполняемого файла. Для запросов не нужны доступ к сети, установленный Go, локальная копия исходного кода или кэш модулей. Сборки без сгенерированных метаданных по-прежнему выводят скомпонованные модули, а отсутствующая атрибуция отображается как `UNKNOWN` или `NULL`.

Вывод охватывает только зависимости Go двоичного файла. Он не включает отношения между зависимостями, не экспортирует документ SPDX или CycloneDX и не является ни полным SBOM развертывания, ни заключением о соответствии лицензионным требованиям.
