StackQL предоставляет ИИ-агентам тот же SQL-интерфейс, с помощью которого люди выполняют запросы к облачным и SaaS-сервисам, создают в них ресурсы и управляют ими. Агент выясняет, что предоставляет провайдер, проверяет запрос до его выполнения, считывает текущее состояние инструкцией `SELECT` и изменяет его инструкциями `INSERT`, `UPDATE` и `DELETE`, без файла состояния и без отдельного SDK для каждого облака.

## Как подключаются агенты {#how-agents-connect}

- **MCP через stdio** для редакторов и настольных клиентов, таких как Claude Desktop, Cursor и Continue. Клиент сам запускает команду `stackql mcp --mcp.server.type=stdio`. См. [MCP-сервер](/command-line-usage/mcp).
- **MCP через HTTP** для автономных агентов и средств автоматизации, которые подключаются к долго работающему процессу `stackql mcp` или `stackql srv`, с аутентификацией по токену bearer и необязательным TLS.
- **Встроенный MCP** для компилируемых приложений: сервер работает внутри процесса приложения на Go, Rust, Swift, Kotlin, .NET и Gleam. См. [Встроенный MCP](/mcp/embedded).
- **Сетевой протокол PostgreSQL** через [`stackql srv`](/command-line-usage/srv) для фреймворков агентов, блокнотов и инструментов BI, которые уже работают с Postgres.

## Быстрый старт с Claude Desktop {#quick-start-with-claude-desktop}

Установите сервер из Anthropic Connector Directory (рекомендуется) или из скачиваемого пакета MCP Bundle либо зарегистрируйте сервер вручную в файле `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "stackql": {
      "command": "stackql",
      "args": ["mcp", "--mcp.server.type=stdio"],
      "env": {
        "AWS_ACCESS_KEY_ID": "your-aws-access-key-id",
        "AWS_SECRET_ACCESS_KEY": "your-aws-secret-access-key"
      }
    }
  }
}
```

Укажите учетные данные только для тех провайдеров, которые вы планируете использовать. Полное описание, включая скачивание пакетов и использование файла учетных данных, см. на странице [Использование StackQL с Claude Desktop](/getting-started/claude-desktop).

## Что может агент {#what-an-agent-can-do}

MCP-сервер предоставляет небольшой типизированный набор инструментов. Каждый инструмент возвращает текстовое отображение для модели и структурированную полезную нагрузку для программных клиентов.

- **Обнаружение**: `list_providers`, `list_services`, `list_resources`, `list_methods` и `describe_method` обходят иерархию провайдера и возвращают входные данные и выходные поля каждой операции, поэтому обязательные параметры `WHERE` известны еще до написания запроса.
- **Проверка и чтение**: `validate_select_query` выполняет синтаксический анализ и планирование инструкции `SELECT` без ее запуска; `run_select_query` выполняет ее.
- **Изменение**: `run_mutation_query` выполняет инструкции `INSERT`, `UPDATE`, `REPLACE` и `DELETE`; `run_lifecycle_operation` выполняет операции жизненного цикла `EXEC`. Оба инструмента контролируются режимом сервера, описанным ниже.
- **Обслуживание**: `server_info`, `list_registry`, `pull_provider` и `reload_credentials`.

Полный справочник с входными данными, правилами контроля и примером промпта для каждого инструмента см. на странице [MCP-инструменты](/mcp).

## Защитные механизмы {#guardrails}

Режим сервера задает контракт безопасности для всего сеанса:

| Режим | `SELECT` / метаданные | `INSERT` / `UPDATE` / `REPLACE` | `DELETE` / `EXEC` |
|--|--|--|--|
| `read_only` | разрешено | отклонено | отклонено |
| `safe` (по умолчанию) | разрешено | требуется подтверждение | требуется подтверждение |
| `delete_safe` | разрешено | разрешено | требуется подтверждение |
| `full_access` | разрешено | разрешено | разрешено |

"Требуется подтверждение" работает через MCP elicitation: клиенты, которые поддерживают эту возможность (Claude Desktop, Cursor, Continue), показывают пользователю имя инструмента, класс запроса и SQL и ждут решения, прежде чем что-либо будет выполнено; запросы клиентов, которые не объявляют эту возможность, отклоняются. Каждый вызов инструмента записывается в журнал аудита, HTTP-прослушиватели требуют токен bearer, если они явно не открыты с помощью `allow_unauthenticated`, а учетные данные загружаются из среды или из файла dotenv, и значения секретов никогда не возвращаются клиенту. Подробнее см. [Режимы сервера](/command-line-usage/mcp#server-modes), [Аутентификация HTTP-клиентов](/command-line-usage/mcp#http-client-authentication) и [Журнал аудита](/command-line-usage/mcp#audit-log).
