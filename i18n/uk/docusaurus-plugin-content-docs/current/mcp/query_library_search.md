Шукає в [StackQL Query Library](pathname:///docs/query-library/) шаблони, що відповідають наміру, описаному природною мовою. Звертайтеся до нього, перш ніж писати SQL з нуля, а потім передайте `id` результату в [`query_library_get`](/mcp/query_library_get), щоб переглянути шаблон і перевірити його параметри.

Інструмент лише отримує вміст бібліотеки. Він не виконує SQL, не викликає хмарні API і не потребує облікових даних провайдера.

[[ Огляд MCP ]](/command-line-usage/mcp) [[ `query_library_get` ]](/mcp/query_library_get) [[ `validate_select_query` ]](/mcp/validate_select_query)

## Вхідні дані {#inputs}

| Аргумент | Обов'язковий | Опис |
|--|--|--|
|`intent`|Так|Опис завдання природною мовою.|
|`provider`|Ні|Фільтр за провайдером, наприклад `aws`.|
|`service`|Ні|Фільтр за сервісом, наприклад `s3`.|
|`tags`|Ні|Масив тегів. Запис має відповідати кожному переданому тегу.|
|`include_mutations`|Ні|Включати шаблони змінення даних. За замовчуванням: `false`; ігнорується в режимі `read_only`, де записи змінення даних завжди виключено.|
|`limit`|Ні|Максимальна кількість збігів. За замовчуванням `5`, якщо значення не вказано або воно не додатне; не більше `20`.|
|`format`|Ні|Формат текстового відображення: `markdown` або `json`. Якщо його не вказано, використовується налаштування відображення сервера (за замовчуванням `markdown`).|

* * *

## Вихідні дані {#output}

Текстовий вивід за замовчуванням - ранжована таблиця зі стовпцями `id`, `title`, `mutation`, `required_params` і `score`, після якої йдуть посилання на джерело та, за наявності, рекомендації на випадок відсутності збігу. Структуроване корисне навантаження містить:

| Поле | Опис |
|--|--|
|`hits`|Ранжовані записи з `id`, `title`, необов'язковим `description`, `providers`, `services` і `required_params`, а також `mutation` і `score`. Повні оголошення параметрів отримуйте далі за допомогою `query_library_get`.|
|`miss`|`true`, якщо збігів немає або найвища оцінка нижча за поріг збігу. Найближчі збіги з низькою оцінкою все одно можуть повертатися.|
|`guidance`|У разі відсутності збігу спрямовує агента до вказівок сервера, інструментів виявлення та `validate_select_query`, щоб він сам склав запит.|
|`source_tier`|Джерело вмісту: `primary`, `fallback` або `snapshot`.|
|`source_url`|URL або вбудований шлях використаного каталогу для цитування.|
|`stale`|Якщо `true`, вміст надано з кешу або вбудованого знімка після помилки отримання.|

Застарілі записи виключено. Сервер кешує каталог і в разі потреби може перейти від розміщеної бібліотеки до її джерела на GitHub і вбудованого знімка.

## Контроль {#gating}

Дозволено в усіх режимах сервера з урахуванням налаштованого списку дозволених інструментів. Схвалення чи облікові дані провайдера не потрібні. Пошук шаблонів змінення даних не дає дозволу на їх виконання.

* * *

## Приклад {#example}

Аргументи інструмента:

```json
{
  "intent": "List S3 bucket names and regions",
  "provider": "aws",
  "service": "s3",
  "limit": 5
}
```

Використайте `id` з `hits`, наприклад `aws/s3/buckets-list`, з [`query_library_get`](/mcp/query_library_get). Якщо `miss` має значення `true`, перегляньте найближчі шаблони як орієнтир або скористайтеся [`list_methods`](/mcp/list_methods) і [`describe_method`](/mcp/describe_method), перш ніж писати SQL.
