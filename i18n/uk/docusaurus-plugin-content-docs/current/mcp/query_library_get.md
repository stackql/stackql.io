Отримує запис [Query Library](pathname:///docs/query-library/) за ідентифікатором `id`, який повернув [`query_library_search`](/mcp/query_library_search).

Якщо `params` не вказано або він порожній, інструмент повертає необроблений шаблон, оголошення параметрів і примітки. Якщо передано непорожній об'єкт `params`, сервер перевіряє значення й підставляє їх у шаблон. Інструмент повертає SQL, лише якщо формування вдалося. Моделі не потрібно підставляти значення самостійно.

Цей інструмент не виконує SQL і не перевіряє хмарні облікові дані. Його перевірка параметрів відрізняється від [`validate_select_query`](/mcp/validate_select_query), який виконує синтаксичний аналіз і планування інструкції `SELECT` для встановленого провайдера.

## Вхідні дані {#inputs}

| Аргумент | Обов'язковий | Опис |
|--|--|--|
|`id`|Так|Ідентифікатор запиту з результатів пошуку, наприклад `aws/s3/buckets-list`.|
|`params`|Ні|Об'єкт, що зіставляє оголошені назви параметрів зі значеннями. Не вказуйте його або передайте `{}`, щоб переглянути шаблон без формування.|
|`format`|Ні|Формат текстового відображення: `markdown` або `json`. Якщо його не вказано, використовується налаштування відображення сервера (за замовчуванням `markdown`).|

Невідомі параметри відхиляються. Обов'язкові параметри без переданих значень або значень за замовчуванням перелічуються в `missing_params`. Передані значення перевіряються на відповідність оголошеним типам і обмеженням; невизначені заповнювачі вважаються помилками.

## Вихідні дані {#output}

Текстовий вивід за замовчуванням - блок KV з ідентифікаційними даними, статусом змінення даних, наступним інструментом, ознакою коректності, посиланнями на джерела, а також шаблоном, сформованим SQL або помилками, якщо вони є. Для повних метаданих використовуйте структуроване корисне навантаження або `format: "json"`:

| Поле | Опис |
|--|--|
|`id`, `title`, `description`|Ідентифікація запису й короткий опис.|
|`mutation`, `verb`|Чи змінює запис ресурси і, якщо оголошено, тип його операції (`select`, `mutation` або `lifecycle`).|
|`next_tool`|Інструмент виконання для запису: `run_select_query`, `run_mutation_query` або `run_lifecycle_operation`. Отримання запису його не викликає.|
|`params`|Оголошення параметрів з назвами, типами, ознаками обов'язковості, а також значеннями за замовчуванням, описами, прикладами, переліками або шаблонами регулярних виразів, якщо вони є.|
|`template`, `notes`|Необроблений шаблон і примітки автора; повертаються, якщо `params` не вказано або він порожній.|
|`rendered`, `valid`|Чи було виконано спробу формування і чи вдалася вона. Обидва мають значення `false` під час перегляду необробленого шаблону.|
|`sql`|Сформований SQL; присутній лише після успішного формування.|
|`missing_params`, `unknown_params`, `errors`|Подробиці перевірки, якщо формування не вдалося. Не виконуйте SQL, доки їх не усунено.|
|`auth`, `permissions`|Якщо оголошено, змінні середовища з обліковими даними й нативні дозволи провайдера, потрібні для виконання. Саме отримання не потребує ні того, ні іншого.|
|`cost`, `outputs`, `related`|Якщо оголошено, підказки щодо fan-out і витрат, описи стовпців результату й ідентифікатори пов'язаних записів.|
|`doc_url`|Сторінка бібліотеки, зручна для читання людиною.|
|`source_tier`, `source_url`, `stale`|Походження вмісту: `primary`, `fallback` або `snapshot`, його URL або вбудований шлях, а також ознака того, чи було вміст надано з кешу або знімка після помилки отримання.|

Для невідомого або неправильно сформованого ідентифікатора інструмент повертає помилку. Щоб знайти допустимі ідентифікатори, використовуйте `query_library_search`.

* * *

## Контроль {#gating}

Дозволено в усіх режимах сервера з урахуванням налаштованого списку дозволених інструментів. Отримання або формування шаблону змінення даних чи операції життєвого циклу не має побічних ефектів у хмарі й не потребує схвалення. Виконання поверненого SQL - окремий виклик, який регулює [режим](/command-line-usage/mcp#server-modes) сервера.

## Приклад {#example}

Спочатку перегляньте запис:

```json
{
  "id": "aws/s3/buckets-list"
}
```

Потім передайте його обов'язковий регіон маршрутизації:

```json
{
  "id": "aws/s3/buckets-list",
  "params": {
    "region": "us-east-1"
  }
}
```

Перевіривши `rendered` і `valid`, перевірте повернену інструкцію `SELECT` за допомогою [`validate_select_query`](/mcp/validate_select_query). Виконайте її інструментом, назву якого вказано в `next_tool`: передайте повернене значення `sql` і встановіть для `source` значення `id` запису бібліотеки, щоб зазначити джерело. Під час виконання потрібні облікові дані та дозволи провайдера.
