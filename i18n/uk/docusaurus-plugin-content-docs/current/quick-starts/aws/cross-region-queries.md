# Асинхронні запити між регіонами за допомогою StackQL

У цьому посібнику ми покажемо потужну можливість StackQL: виконання запитів до ресурсів у кількох регіонах AWS та їх агрегування.  Це передбачає численні запити до API на різні кінцеві точки, які виконуються асинхронно.  Для користувача це відбувається непомітно й прозоро.  

> StackQL - це потужний інструмент розробника, що дає змогу виконувати запити до хмарної інфраструктури й ресурсів і розгортати їх за допомогою синтаксису SQL.  

Перевірено з <span class="tutorial_tested_on">вбудований бекенд SQL</span> <span class="tutorial_tested_on">бекенд SQL postgres</span> <span class="tutorial_tested_on">macos</span> <span class="tutorial_tested_on">linux</span> <span class="tutorial_tested_on">powershell</span>

## Розуміння регіонів і ресурсів AWS {#understanding-aws-regions-and-resources}

Ресурси AWS розміщено в багатьох розташуваннях по всьому світу.  Ці розташування складаються з регіонів і зон доступності, які дають змогу користувачам розміщувати екземпляри та зберігати дані в різних місцях.

## Проблема з регіонами AWS... {#the-problem-with-aws-regions}

Під час роботи з AWS важливо розуміти, що AWS Management Console відображає ресурси в межах регіону: вона дає змогу користувачам взаємодіяти з ресурсами й керувати ними щоразу лише в одному конкретному регіоні.  Так само команди AWS Command Line Interface (CLI) і набори засобів розробки програмного забезпечення (SDK) використовують регіон як точку входу для операцій, тому для виконання команд або запуску програм потрібно вказати регіон.  

> Регіональна структура хмарних сервісів створює складнощі, коли ресурси охоплюють кілька регіонів.  Крім того, порушення безпеки, зокрема експлойти для майнінгу криптовалют, часто задіюють ресурси в різних місцях, поза межами основного регіону, який зазвичай використовують організації.

## Зазначення регіонів у запитах StackQL {#specifying-regions-in-stackql-queries}

За допомогою StackQL ви можете вказувати регіони, щоб звертатися до ресурсів у різних географічних розташуваннях.  Це особливо корисно для керування ресурсами, розподіленими по всьому світу.

### Приклад: виведення списку екземплярів EC2 у кількох регіонах {#example-listing-ec2-instances-across-multiple-regions}

```sql
SELECT instance_id, region
FROM aws.ec2.instances
WHERE region IN ('us-east-1', 'eu-west-1');
```

Цей запит повертає список екземплярів EC2 з регіонів `us-east-1` (Північна Вірджинія) і `eu-west-1` (Ірландія) та показує, як StackQL може отримувати дані з різних регіонів одним запитом.  Це також можна використовувати з агрегатними запитами, наприклад:  

```sql
SELECT region, COUNT(*) as num_functions
FROM aws.lambda.functions
WHERE region IN (
  'us-east-1','us-east-2','us-west-1','us-west-2',
  'ap-south-1','ap-northeast-3','ap-northeast-2',
  'ap-southeast-1','ap-southeast-2','ap-northeast-1',
  'ca-central-1','eu-central-1','eu-west-1',
  'eu-west-2','eu-west-3','eu-north-1','sa-east-1')
GROUP BY region;
```

## Потужність асинхронних запитів {#the-power-of-asynchronous-queries}

StackQL виконує ці запити між регіонами асинхронно й надсилає кілька паралельних запитів до API AWS.  Це забезпечує ефективне отримання даних: не потрібно чекати завершення запиту для одного регіону, перш ніж переходити до наступного.

## Висновок {#conclusion}

Асинхронні запити між регіонами в StackQL - це надійний і ефективний спосіб керування ресурсами AWS у різних географічних розташуваннях.  Завдяки синтаксису цих запитів, подібному до SQL, StackQL спрощує складні завдання керування хмарою, що робить його незамінним інструментом для розробників і адміністраторів хмарних середовищ, які прагнуть оптимізувати свою інфраструктуру AWS.
