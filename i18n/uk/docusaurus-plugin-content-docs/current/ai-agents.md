StackQL надає агентам ШІ той самий інтерфейс SQL, за допомогою якого люди виконують запити до хмарних сервісів і сервісів SaaS, створюють у них ресурси та керують ними. Агент з'ясовує, що надає провайдер, перевіряє запит перед виконанням, читає поточний стан за допомогою `SELECT` і змінює його за допомогою `INSERT`, `UPDATE` і `DELETE`, без файлу стану й без окремого SDK для кожної хмари.

## Як підключаються агенти {#how-agents-connect}

- **MCP через stdio** для редакторів і настільних клієнтів, як-от Claude Desktop, Cursor і Continue. Клієнт сам запускає команду `stackql mcp --mcp.server.type=stdio`. Див. [Сервер MCP](/command-line-usage/mcp).
- **MCP через HTTP** для автономних агентів і засобів автоматизації, що підключаються до постійно запущеного процесу `stackql mcp` або `stackql srv`, з автентифікацією за токеном bearer і необов'язковим TLS.
- **Вбудований MCP** для скомпільованих застосунків: сервер працює в процесі застосунку на Go, Rust, Swift, Kotlin, .NET і Gleam. Див. [Вбудований MCP](/mcp/embedded).
- **Мережевий протокол PostgreSQL** через [`stackql srv`](/command-line-usage/srv) для фреймворків агентів, блокнотів та інструментів BI, які вже працюють із Postgres.

## Швидкий старт із Claude Desktop {#quick-start-with-claude-desktop}

Встановіть сервер з Anthropic Connector Directory (рекомендовано) або із завантажуваного MCP Bundle, або зареєструйте його вручну у файлі `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "stackql": {
      "command": "stackql",
      "args": ["mcp", "--mcp.server.type=stdio", "--tls.allowInsecure"],
      "env": {
        "AWS_ACCESS_KEY_ID": "your-aws-access-key-id",
        "AWS_SECRET_ACCESS_KEY": "your-aws-secret-access-key"
      }
    }
  }
}
```

Вказуйте облікові дані лише для тих провайдерів, якими плануєте користуватися. Докладні вказівки, зокрема завантаження пакета та використання файлу облікових даних, наведено на сторінці [Використання StackQL із Claude Desktop](/getting-started/claude-desktop).

## Що може агент {#what-an-agent-can-do}

Сервер MCP надає невеликий типізований набір інструментів. Кожен інструмент повертає відформатоване відображення для моделі та структуроване корисне навантаження для програмних клієнтів.

- **Виявлення**: `list_providers`, `list_services`, `list_resources`, `list_methods` і `describe_method` проходять ієрархією провайдера й повертають вхідні параметри та вихідні поля кожної операції, тож обов'язкові параметри `WHERE` відомі ще до написання запиту.
- **Перевірка й читання**: `validate_select_query` виконує синтаксичний аналіз і планування інструкції `SELECT` без її запуску; `run_select_query` виконує її.
- **Змінення**: `run_mutation_query` виконує `INSERT`, `UPDATE`, `REPLACE` і `DELETE`; `run_lifecycle_operation` виконує операції життєвого циклу `EXEC`. Обидва інструменти контролюються режимом сервера, описаним нижче.
- **Обслуговування**: `server_info`, `list_registry`, `pull_provider` і `reload_credentials`.

Повний довідник із вхідними даними, поведінкою контролю та прикладом промпту для кожного інструмента див. на сторінці [Інструменти MCP](/mcp).

## Запобіжники {#guardrails}

Режим сервера визначає контракт безпеки для всього сеансу:

| Режим | `SELECT` / метадані | `INSERT` / `UPDATE` / `REPLACE` | `DELETE` / `EXEC` |
|--|--|--|--|
| `read_only` | дозволено | відхилено | відхилено |
| `safe` (за замовчуванням) | дозволено | потрібне схвалення | потрібне схвалення |
| `delete_safe` | дозволено | дозволено | потрібне схвалення |
| `full_access` | дозволено | дозволено | дозволено |

"Потрібне схвалення" означає використання elicitation MCP: клієнти, що його підтримують (Claude Desktop, Cursor, Continue), показують користувачеві назву інструмента, клас запиту та SQL і чекають рішення, перш ніж щось буде виконано; клієнти, які не оголошують цієї можливості, отримують відмову. Кожен виклик інструмента записується в журнал аудиту, прослуховувачі HTTP вимагають токен bearer, якщо їх явно не відкрито за допомогою `allow_unauthenticated`, а облікові дані завантажуються із середовища або файлу dotenv, і значення секретів ніколи не повертаються клієнту. Докладніше див. [Режими сервера](/command-line-usage/mcp#server-modes), [Автентифікація клієнтів HTTP](/command-line-usage/mcp#http-client-authentication) і [Журнал аудиту](/command-line-usage/mcp#audit-log).
