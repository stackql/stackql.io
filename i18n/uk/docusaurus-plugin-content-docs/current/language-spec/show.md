Використовується для виведення списку елементів колекції, наприклад, усіх сервісів, доступних у провайдері, або всіх ресурсів, доступних у певному сервісі. Також показує версію, учасників і програмні залежності запущеного двійкового файлу StackQL.

Див. також:
[[ Ієрархія ресурсів StackQL ]](/getting-started/resource-hierarchy)

* * * 

## Синтаксис {#syntax}

*showStatement::=*

<RailroadDiagram 
type="show"
/>

&nbsp;  
&nbsp;  

```sql
SHOW [ EXTENDED ]
{ PROVIDERS | SERVICES | RESOURCES | METHODS }
[ { IN | FROM } { <provider> | <service> | <resource> } ]
[ { LIKE '<pattern>' | WHERE <expression> } ];

SHOW [ EXTENDED ] INSERT INTO <resource>;
SHOW [ EXTENDED ] VERSION;
SHOW [ EXTENDED ] CONTRIBUTORS;
SHOW [ EXTENDED ] DEPENDENCIES [ LIKE '<pattern>' ];
```

`VERSION`, `CONTRIBUTORS` і `DEPENDENCIES` не потребують налаштування провайдерів чи автентифікації. `DEPENDENCIES` підтримує лише необов'язкове речення `LIKE`; `IN`, `FROM`, `WHERE` і `LIMIT` не підтримуються.

### Перегляд версії StackQL {#show-the-stackql-version}

Повертає версію запущеного процесу StackQL. Корисно в режимах shell, exec і сервера з мережевим протоколом Postgres, коли потрібно переконатися, яка збірка відповідає на запити. Ці самі відомості також надає інструмент MCP `server_info`.

```sql
-- Returns the version of the running StackQL process
SHOW VERSION;
```
<details>
<summary><em><strong>Повертає:</strong></em></summary>

```
|---------|
| version |
|---------|
| 1.0.888 |
|---------|
```

</details>

Скористайтеся необов'язковим ключовим словом `EXTENDED`, щоб також отримати коміт git, позначку часу збірки й платформу збірки:

```sql
-- Returns version plus build provenance
SHOW EXTENDED VERSION;
```
<details>
<summary><em><strong>Повертає:</strong></em></summary>

```
|---------|---------|----------------------|----------|
| version | commit  |      build_date      | platform |
|---------|---------|----------------------|----------|
| 1.0.888 | f7b4116 | 2026-11-05T00:26:03Z | Windows  |
|---------|---------|----------------------|----------|
```

</details>

> Інструкція `SHOW VERSION` не потребує налаштування провайдерів, реєстру чи автентифікації, і її безпечно виконувати в будь-якому сеансі.

### Виведення списку учасників StackQL {#list-stackql-contributors}

Повертає рейтинг учасників, вбудований у запущений двійковий файл StackQL. Знімок відзначає учасників GitHub, які є людьми й поставили зірку репозиторію StackQL, і впорядковує їх за кількістю внесків, від найбільшої. Знімок фіксований для кожної збірки й не виконує запитів до GitHub під час виконання.

```sql
SHOW CONTRIBUTORS;
SHOW EXTENDED CONTRIBUTORS;
```

| Стовпець | Опис |
| --- | --- |
| `contributor` | Ім'я користувача GitHub |
| `contributions` | Кількість внесків, записана в знімку; включається з `EXTENDED` |

### Виведення списку програмних залежностей двійкового файлу {#list-the-binarys-software-dependencies}

Повертає офлайнову інвентаризацію модулів Go, включених у запущений виконуваний файл StackQL. Це полегшений перелік компонентів програмного забезпечення (SBOM) для двійкового файлу, до якого користувачі й агенти можуть виконувати запити під час роботи StackQL. Він охоплює прямі й транзитивні залежності Go; встановлені визначення провайдерів, окремі обгортки, інструменти CI, модулі лише для тестування, образи контейнерів і пакети операційної системи до нього не входять.

```sql
SHOW DEPENDENCIES;
SHOW EXTENDED DEPENDENCIES;
```

Стовпці за замовчуванням: `name`, `version`, `license` і `description`. Ключове слово `EXTENDED` додає решту стовпців, наведених нижче, не змінюючи того, які рядки повертаються.

| Стовпець | Опис |
| --- | --- |
| `name` | Фактичний шлях модуля Go: шлях заміни, якщо застосовується заміна модуля Go |
| `version` | Точна версія модуля, включно з версіями попередніх випусків і псевдоверсіями |
| `license` | Виявлений ідентифікатор ліцензії; `UNKNOWN`, якщо ліцензію не визначено або вона неоднозначна |
| `description` | Опис компонента, якщо він доступний |
| `source_url` | URL репозиторію з вихідним кодом; включається з `EXTENDED` |
| `license_url` | URL файлу ліцензії, закріплений за тегом модуля або ревізією вихідного коду; включається з `EXTENDED` |
| `purl` | Package URL, що ідентифікує модуль і версію; включається з `EXTENDED` |
| `checksum` | Контрольна сума модуля Go з префіксом `h1:`, а не дайджест SHA-256 виконуваного файлу чи архіву; включається з `EXTENDED` |
| `original_name` | Початково запитаний шлях модуля, якщо застосовується заміна; включається з `EXTENDED` |
| `original_version` | Початково запитана версія, якщо застосовується заміна; включається з `EXTENDED` |

Рядки впорядковано за фактичним іменем модуля, а потім за версією. Для замін використовуються версія, контрольна сума й атрибуція заміни. Для модулів без замін `original_name` і `original_version` мають значення `NULL`. Інші недоступні метадані також мають значення `NULL`, за винятком невизначених ліцензій, для яких указується `UNKNOWN`. Заміни на шляхи локальної файлової системи не мають вигаданих версії, URL чи контрольної суми.

Скористайтеся реченням `LIKE`, щоб шукати за фактичним іменем модуля, початковим іменем модуля або описом:

```sql
SHOW DEPENDENCIES LIKE '%stackql%';
SHOW EXTENDED DEPENDENCIES LIKE '%vitess%';
SHOW EXTENDED DEPENDENCIES LIKE 'github.com/chzyer/readline';
```

Зіставлення виконується без урахування регістру. `%` відповідає нулю або більшій кількості символів, а `_` відповідає рівно одному символу. Пошук у стовпцях ліцензії та версії не виконується. Одинарну лапку всередині рядкового літерала SQL потрібно подвоювати; після декодування рядка SQL зворотні скісні риски сприймаються буквально й не екранують символи узагальнення `LIKE`.

Якщо жоден модуль не відповідає шаблону, результат містить нуль рядків. У форматі CSV зберігаються заголовки стовпців, клієнти мережевого протоколу PostgreSQL зберігають метадані стовпців, а вивід JSON дорівнює `null`.

Інвентаризація поєднує метадані, вбудовані під час збирання, з інформацією про збірку Go виконуваного файлу. Для запитів не потрібні доступ до мережі, встановлений Go, локальна копія вихідного коду чи кеш модулів. Збірки без згенерованих метаданих усе одно повідомляють про скомпоновані модулі, а відсутня атрибуція відображається як `UNKNOWN` або `NULL`.

Вивід охоплює лише залежності Go двійкового файлу. Він не містить відношень між залежностями, не експортує документ SPDX чи CycloneDX і не є ні повним SBOM розгортання, ні висновком про відповідність ліцензійним вимогам.
