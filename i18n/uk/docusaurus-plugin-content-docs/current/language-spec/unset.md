Видаляє змінну сеансу або скидає конфігурацію середовища виконання, встановлену для поточного сеансу за допомогою [`SET`](/language-spec/set).  Доступно в StackQL `v1.0` і новіших версіях.

## Синтаксис {#syntax}

*unsetStatement::=*

&nbsp;  
&nbsp;  

```sql
UNSET [ SESSION ] <target> [, <target> ...];
```

__*target*__  
Будь-яка ціль, яку приймає інструкція `SET`: ім'я змінної, просте або в подвійних лапках, чи шлях конфігурації в подвійних лапках із префіксом у вигляді знака долара.

__*SESSION*__  
Необов'язкове ключове слово, що позначає єдину наявну область: `UNSET SESSION name` і `UNSET name` - та сама інструкція, оскільки кожна змінна й кожне налаштування конфігурації належать до поточного сеансу.  Інструкція `UNSET GLOBAL` відхиляється з помилкою `configuration scope "global" is not supported; use SESSION`.

Інструкція `UNSET name` еквівалентна інструкції `SET name = DEFAULT`.  Цілі в одному списку видаляються в порядку переліку, а видалення імені, яке не встановлено, не є помилкою.  Розіменування змінної після скасування її значення завершується помилкою ще до надсилання будь-якого запиту до провайдера.

| Ціль | Дія |
|--|--|
| `name` | Видаляє змінну сеансу. |
| `"$.auth.<provider>.<field>"` | Видаляє це поле з контексту автентифікації провайдера в сеансі.  Значення, чинне до перевизначення, не відновлюється. |
| `"$.providers.<alias>"` | Видаляє прив'язку псевдоніма провайдера. |
| `"$.secrets.<name>"` | Видаляє секрет зі сховища сеансу.  Для постійного сховища ОС це видаляє збережене значення. |
| `"$.secret_store"` | Скасовує поточну прив'язку сховища й починає з порожньої пам'яті сеансу.  Значення, уже збережені в сховищі ОС, не видаляються. |

## Приклади {#examples}

### Видалення змінної {#remove-a-variable}

Змінну видалено із сеансу, тому закоментований запит завершується помилкою `variable "$region" is not defined`, а не виконується з неактуальним або порожнім значенням.  Щоб знову використовувати це ім'я, встановіть його ще раз.

```sql
SET region = 'ap-southeast-2';
UNSET region;

/*
SELECT name FROM aws.s3.buckets WHERE region = $region;
-- FAILS with variable "$region" is not defined
*/
```

### Видалення кількох цілей {#remove-several-targets}

Одна інструкція може видаляти змінні й шляхи конфігурації разом, а цілі обробляються послідовно.  Тут в одному списку видаляються проста змінна, змінна з іменем, що містить крапки, і перевизначення облікових даних.

```sql
UNSET region, "providers.saved", "$.auth.github.credentialsenvvar";
```

### Явне зазначення області сеансу {#make-the-session-scope-explicit}

Ці дві інструкції роблять те саме: `SESSION` називає єдину наявну область.  Явна форма підходить для скриптів, які також виконуються в базах даних, що розрізняють стан сеансу й глобальний стан.  Закоментована інструкція завершується помилкою, оскільки спільного стану немає.

```sql
UNSET region;
UNSET SESSION region;

/*
UNSET GLOBAL region;
-- FAILS with configuration scope "global" is not supported; use SESSION
*/
```

### Скасування перевизначення облікових даних {#clear-a-credential-override}

Поле, раніше встановлене за допомогою `SET "$.auth.github.credentialsenvvar"`, видаляється з контексту автентифікації провайдера GitHub у сеансі, а інші поля цього контексту залишаються незмінними.  Значення, чинне до перевизначення, не відновлюється, тому встановіть поле знову, якщо воно ще потрібне провайдеру.

```sql
UNSET "$.auth.github.credentialsenvvar";
```

### Видалення псевдоніма провайдера та його секрету {#remove-a-provider-alias-and-its-secret}

Псевдонім `production` прив'язано за допомогою `SET "$.providers.production"`, і через `auth_secret` він посилається на секрет, збережений у `$.secrets.production`.  Видалення обох в одній інструкції скасовує прив'язку, тож `production.s3.buckets` більше не є допустимим відношенням, і видаляє секрет зі сховища сеансу.  Ключове слово `SESSION` тут, як і скрізь, необов'язкове.

```sql
UNSET SESSION "$.providers.production", "$.secrets.production";
```
